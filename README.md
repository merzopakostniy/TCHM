# ТЧМ

Приложение Flutter для iOS и Android: депо, колонны, карточки машинистов,
контроль нормативов и экспорт PDF. Рабочий сервер — собственный API
в Yandex Cloud, данные — в YDB.

## Запуск

```bash
flutter pub get
flutter run
```

Обычный запуск и все release/profile-сборки используют Yandex API.
`YANDEX_API` и `FIREBASE_CONFIGURED` больше не выбирают сервер. Ошибка сети
не переключает приложение на Firebase или локальные данные.

Демо для проверки интерфейса — только в debug, данные хранятся в памяти:

```bash
flutter run --dart-define=DEMO=true
```

Снимки интерфейса: `flutter run --dart-define=SHOT=0` (также только debug).
В release/profile флаги DEMO и SHOT игнорируются.

## Вход и права

Регистрация по ключу депо: гость или ТЧМ, затем подтверждение почты.
Ключ, статус аккаунта, роль и доступ к депо проверяет сервер.
Администратор управляет всеми депо и аккаунтами, но не блокировкой базы.
Разработчик входит обычным способом по почте и паролю; роль назначается
доверенной серверной операцией. Отдельного пароля разработчика в приложении нет.

## Android release

```bash
flutter analyze
flutter test
flutter build appbundle --release
```

Результат: `build/app/outputs/bundle/release/app-release.aab`.
Подпись берётся из локального `android/key.properties`; ключи не коммитить.
Для проверки на телефоне: `flutter build apk --release`.
iOS release отдельно требует macOS, настроенной подписи и проверки устройства.

## Проверки сервера

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
.venv/bin/python -m unittest discover -s backend -p 'test_*.py'
```

Обычные серверные тесты используют заглушки БД и тестовые JWT.
`backend/check_column_creation.py` — отдельная интеграционная проверка:
создаёт и удаляет изолированную таблицу YDB. Её запуск требует настроенных
YDB_ENDPOINT, YDB_DATABASE, YDB_ACCESS_TOKEN и тестового JWT_SECRET.

## Старый Firebase

Новый клиент не инициализирует Firebase и не выбирает его репозитории.
Старые классы и инструменты миграции оставлены в исходниках для сопровождения.
Рабочие данные и существующие роли Firebase автоматически не меняются.

Подготовленные `firestore.rules` закрывают создание профилей с клиента,
изменение роли, депо, табельного и назначенной колонны. Новая регистрация
проходит в Yandex Cloud. Старые профили без явного активного статуса или депо не получают доступ,
включая прежних разработчиков. Пользователи регистрируются заново в новом
приложении через Yandex API; привязка к ТЧ-16 автоматически не назначается. Проверка существующих
привилегированных аккаунтов нужна отдельно, поскольку старые правила могли
разрешать их создание.

Тестирование правил (нужны Node.js, Firebase CLI и Java):

```bash
npm ci --prefix tool
firebase emulators:exec --project demo-tchm-release --config firebase.test.json --only firestore 'node tool/test_firestore_rules.cjs'
```

Тест использует только локальный порт 18080 и демонстрационный проект.
Перед публикацией правил нужно сверить опубликованный набор и сохранить его
для отката: нельзя случайно ослабить уже включённую полную блокировку.
Статус фактической публикации указан в отчёте о готовности релиза.
